        About myProfile

        How this works, and why it needs Firebase.

        Open the site

        Why Firebase, for a portfolio?

        The portfolio is a static site on GitHub Pages: it can show things, but it can’t receive anything or change without a new commit. Firebase (free Spark plan) adds the two things a static site can’t do:

        • A database (Firestore) that holds your published resume and visitors’ messages, so you can edit from your phone and the site updates without a deploy.
        • Sign-in (Firebase Authentication, Google) so only thrishankkuntimaddi@gmail.com can edit or read messages.

        How the resume flows

        1. You edit here. Every change autosaves as a private draft (only you can read it).
        2. Publish copies the draft to site/resume and keeps a copy in Versions so you can roll back.
        3. The site reads site/resume with one small request when someone opens or downloads the resume, then draws the same one-page layout you see here and builds the PDF in the visitor’s browser (selectable text, working links, ATS-friendly).
        4. If Firebase can’t be reached, the site falls back to the last PDF in the repo (resume/).

        How messages flow

        The “Send a message” form on the site (footer, the themes page, and Ask Pip) writes to messages. Visitors can only create a message of a fixed shape and size; they can’t read, change or delete any. You see them here instantly, sorted into Feedback, Compliments, Help center and plain Messages.

        Security

        • Only thrishankkuntimaddi@gmail.com, signed in with Google, gets in. Any other account is signed out at once, and the database refuses it anyway.
        • Changing anything also needs a sign-in from the last 30 days.
        • Account & devices (the person icon at the top on a phone) lists every device and signs any of them out. Sign out everywhere is enforced by the database: every older sign-in is refused, on any device.
        • The app locks with your fingerprint / face / screen lock on open and after 5 minutes away; in the Android app, screenshots and the recent-apps preview are blocked.
        • The Firebase web config in the code is public by design. Access is enforced by firestore.rules in the repo, deployed with firebase deploy --only firestore:rules.
        • Owner = a signed-in Google account with the verified email thrishankkuntimaddi@gmail.com. Everyone else is read-only on the published resume and help answers.
        • Messages have a hidden spam trap and a cooldown in the browser. If spam ever becomes a problem, turn on Firebase App Check (free) in the console.

        Costs

        Free. The Spark plan allows 50,000 reads and 20,000 writes a day. A resume view is one read; a message is one write. No Cloud Functions, no Storage, no billing account needed. An uploaded PDF resume is kept as text in a few database documents (up to 1.1 MB), so it stays free too.

        Reports

        Each visit records the page, device, screen, language, where they came from, and when they leave, how long they stayed and how far they scrolled. The approximate city, state and internet provider come from a free lookup (get.geojs.io) in the visitor’s browser; the IP address itself is never saved. Visits from before this only know the time zone, which is why everyone in India showed as “Calcutta”. Turn the lookup off under Website → Reports.

        Use it as an app

        • iPhone: open this page in Safari → Share → Add to Home Screen.
        • Android: Chrome → ⋮ → Install app (or Add to Home screen).
        • Mac / PC: Chrome or Edge → the install icon in the address bar.

        Writing tips (the FAANG way)

        • One page. The layout shrinks type down to 82% to fit; if it still says “over one page”, cut words, not margins.
        • Bullets: action verb + what you built + measurable result, e.g. “Cut p95 latency from 850ms to 45ms by …”.
        • Bold only the numbers and labels a recruiter should catch in six seconds: **10K+ sessions**.
        • Standard section names (Summary, Experience, Projects, Skills, Education) so ATS parsers find them.
        • Formatting: **bold**, *italic*, [text](https://link).
